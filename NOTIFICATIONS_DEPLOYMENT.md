# Уведомления: реализация и приёмка

Сверено с кодом 20.10.2026. Наличие реализации не означает, что актуальная версия развёрнута на VPS. В рамках этой сверки сервер, БД и доставка Socket.IO не проверялись.

## Состав

- Модель `Notification` в prisma/schema.prisma (`prisma/schema.prisma`; исходник/артефакт не входит в публикацию): получатель, тип, заголовок, сообщение, `read`, `readAt`, `actionUrl`, metadata и дата создания.
- notifications.ts (`src/lib/notifications.ts`; исходник/артефакт не входит в публикацию): запись и чтение; notification-triggers.ts (`src/lib/notification-triggers.ts`; исходник/артефакт не входит в публикацию): функции для событий.
- NotificationBell (`src/components/layout/notification-bell.tsx`; исходник/артефакт не входит в публикацию): список из 20 записей при открытии, счётчик с опросом каждые 30 секунд, отметка прочитанным, переход по `actionUrl`.
- useNotificationSocket (`src/hooks/useNotificationSocket.ts`; исходник/артефакт не входит в публикацию): подключение с cookie, `notification:join`/`notification:leave`; `notification:new` инвалидирует клиентские запросы.

## HTTP API

Маршруты используют `requireApiUser`: NextAuth session cookie либо действующий API Bearer-токен. Записи выбираются для текущего пользователя; PATCH отдельной записи проверяет владельца.

| Метод | Путь | Поведение |
|---|---|---|
| GET | `/api/notifications` | `limit=20`, `offset=0`, `unreadOnly=true` для непрочитанных; новые первыми. `meta.total` равно длине страницы, а не общему числу записей. |
| GET | `/api/notifications/unread-count` | `data.count` непрочитанных |
| PATCH | `/api/notifications/{id}` | Отметить одну запись |
| PATCH | `/api/notifications/mark-all-read` | Отметить непрочитанные записи текущего пользователя |

## Триггеры и ограничения

Назначение исполнителя, изменение статуса, добавление участника и сообщение чата имеют интеграции в соответствующих API/Socket.IO обработчиках. Самоназначение и события самого инициатора исключаются соответствующими функциями. Для `task_mentioned` и `task_deadline_approaching` существуют функции, но их вызовы вне файла определений не найдены: автоматическое распознавание упоминаний и регулярная рассылка дедлайнов не считаются подключёнными.

`createNotification` применяет лимит 100/мин на получателя. `createNotifications` использует `createMany` и отдельную выборку за последние 5 секунд; bulk-путь не вызывает этот limiter и при конкурентных вставках выборка может захватить другие записи.

Событие отправляется через динамический `getSocketIO()` в текущем процессе. Next.js и Socket.IO запускаются отдельно, поэтому этот вызов сам по себе не обеспечивает доставку между процессами; конкретную схему запуска нужно проверить. REST и опрос счётчика остаются отдельными путями чтения. Email, browser push и настройки предпочтений эта подсистема не реализует.

## Приёмка выпуска

Развёртывание выполнять по общей инструкции проекта после проверки схемы и резервной копии. Миграционную историю сверить с существующей БД: наличие отдельной миграции Notification не доказывает bootstrap пустой базы.

На тестовом проекте с двумя пользователями проверить назначение, статус, участника и чат; инициатор не должен получать собственное уведомление. Во второй сессии проверить событие без reload, счётчик, список, переход в задачу и обе отметки прочитанным. Отдельно проверить отказ доступа к чужой записи, восстановление соединения и чтение после перезапуска Socket.IO. Зафиксировать commit, процессы, дату и результаты; этот чеклист пока не означает выполненных проверок.
