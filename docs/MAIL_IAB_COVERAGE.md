# Охват почты при сборе через встроенный браузер

Сбор выполняется из уже авторизованного интерфейса Basemail. Исходные письма и данные входа не передаются в GitHub. Локальные результаты хранятся в `.mail-work/` и не входят в коммиты.

## Что означает полный обход

Наблюдение от 20 октября 2026 года после кнопки «Показать все темы»: интерфейс показывает счётчик **52 594** и **2630 страниц списка**. Эти два числа нельзя автоматически называть количеством сообщений и количеством тем. В отчёте нужны отдельные наблюдаемые показатели:

- страницы списка: обнаруженные, сохранённые, ожидающие, неуспешные;
- уникальные темы по `topicid`: обнаруженные, завершённые, ожидающие;
- страницы внутри каждой темы и все обнаруженные ссылки пагинации;
- уникальные сообщения по паре `(source_instance, source_message_id)`;
- сообщения с позиционным ID, конфликты ID, отсутствующий текст и неподтверждённые вложения;
- начало/конец обхода и время сохранения каждой страницы.

Счётчик интерфейса сохраняется вместе с названием/контекстом и временем наблюдения; пока единица не подтверждена, он не используется как точное ожидаемое количество сообщений. Даже успешный проход 2630 страниц списка не означает, что прочитаны все сообщения внутри переписок.

## Защита от ложного результата

Кнопка «Скрыть все темы» и изменение списка/пагинации подтверждают включённое отображение всех тем. Две темы из предыдущего запуска были результатом фильтра, а не доказательством ограничения прав. Недоступная страница остаётся в очереди. Страница входа, неизвестный DOM, повтор одного и того же содержимого под разными номерами, обрезанный текст и конфликт исходного ID требуют проверки и запрещают заявление о полном архиве.

Сообщения с одинаковым текстом, но разными исходными ID остаются отдельными. Один исходный ID на пересекающихся страницах учитывается один раз; несовпадающие версии содержимого сохраняются для разбора. Позиционный ID не доказывает отсутствие дублей при перестановке сообщений.

Ящик меняется во время обхода. Смещение страниц может вызвать и пересечения, и пропуски; необходимо фиксировать начальные/конечные наблюдения и перепроверить границы, а не вычитать число дублей из счётчика интерфейса. Без стабильного снимка сервера корректная формулировка: «обойдены все обнаруженные страницы за указанный интервал», с отдельной оговоркой о живом источнике.

## Классификация и предложения досок

Для собранных уникальных сообщений проверяется баланс:

`назначено в основные категории + неразобранное = собрано уникальных сообщений`.

Дополнительные теги не увеличивают число сообщений. Темы и сообщения показываются отдельно. Ещё не просмотренные темы/страницы находятся в разделе неполноты сбора, а не в «Неразобранном». Предложения kanban-досок сопровождаются количеством исходных тем/сообщений, полями, этапами работы и уровнем уверенности. Запросы клиентов на отправку чеков не объединяются автоматически с учётом расходов.

## Пределы результата

Открытие темы может изменить её состояние прочтения на стороне Basemail. Сборщик не отправляет, не удаляет и не перемещает письма. Ссылки на вложения и их названия — это метаданные; без скачивания байтов нельзя заявлять, что вложения сохранены. Неизвестные или недоступные вложения отмечаются отдельно.

Статусы охвата:

| Статус | Значение |
|---|---|
| `partial` | Есть незавершённые/ошибочные страницы, темы, пропуски содержимого или конфликты идентичности. |
| `unverified` | Наблюдаемый обход завершён, но независимое доказательство полноты серверного архива и стабильного снимка отсутствует. |
| `complete` | Допустим только при документально подтверждённых единице и границах источника, всех страницах/темах, согласованных ID и отсутствии неразрешённых ошибок; стандартный DOM-обход сам по себе этого не доказывает. |

Публикуемый рабочий журнал содержит только агрегаты и технические выводы. Полный локальный отчёт может содержать частные названия тем и ссылки; его нельзя автоматически включать в PR.

## Проверки реализации

Контроль охвата проверяется на синтетических данных без авторизации и сети:

```powershell
node --test tests/mail/iab-coverage.test.mjs
```

Тесты обращаются к настоящему SQLite-хранилищу: начало и конец списка без промежуточных страниц не дают полный охват; пересекающиеся страницы не удваивают сообщения; одинаковый текст разных ID сохраняется; конфликт ID между темами требует разбора; повтор одного списка под другим номером изолируется; пустая выдача не считается прочитанной темой; ошибки остаются повторяемыми; начальное и конечное значения счётчика сохраняются раздельно.
