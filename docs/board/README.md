## Работа с карточками

Канонический этап — поле **Status** в GitHub Projects. Доска сгруппирована по четырём значениям: **Заведена → В работе → На тестировании → Завершена**. Переносите карточку между колонками или меняйте Status в карточке проекта. Ответственного указывайте в Assignees, намерение, изменения, файлы и результаты проверок — в комментариях issue по [регламенту](../TASK_WORKFLOW.md).

Новую issue добавляйте в проект через раздел Projects и выбирайте «Заведена»; сама форма issue этого не гарантирует. Отдельная метка `status:blocked` обозначает блокировку и требует комментария с причиной и следующим шагом. Прежние метки этапов не заменяют поле Status.

«Завершена» требует успешных релевантных проверок и опубликованных доказательств выполнения критериев. Если проверка выявила ошибку, верните карточку в «В работе»; если результат ещё не проверен, оставьте открытой на тестировании. По состоянию подготовки исправлений #1–#27 находятся в «Заведена», #28 повторно открыта и находится «В работе» до итоговой проверки.

## Настройки и хранение

Представление, поле Status, видимость и встроенные workflows настраиваются в интерфейсе GitHub Projects. Они не хранятся как файлы Git. Инструкция, регламент и справочная документация хранятся в репозитории.

Item closed переводит карточку в «Завершена»; Auto-close issue настроен только на Status «Завершена». Оба действия требуют соблюдения регламента перед закрытием или переносом карточки. Переходы по привязке PR и слиянию PR отключены, чтобы не пропускать тестирование.

[BOARD.md](BOARD.md) — короткая ссылка на этот же проект. Отдельные HTML/JSON-снимки и генераторы для ведения доски не требуются. Состав публикации и план итоговой проверки описаны в [BOARD_PUBLICATION.md](../BOARD_PUBLICATION.md). Документация приложения описывает полный локальный снимок; исходники приложения пока не опубликованы в этом репозитории.
