# Перенос итогового демо в приложение

Уточнение владельца 25.10.2026: основной образец интерфейса и поведения —
`outputs/design/redesign-v1/index.html` (`http://127.0.0.1:3857/`). Предыдущий
частичный перенос не является приёмкой редизайна. Переносятся целые сценарии;
совпадения цвета или отдельных подписей недостаточно. Реальные права, история,
вложения, черновики и уведомления используют существующие серверные механизмы.
Демонстрационный переключатель роли не выдаёт production-права.

## Изменения исходников

- Главная: вопрос, два направления, число собственных активных обращений,
  баннер ожидания ответа, последние реальные обращения.
- Меню: глобальное добавление с выбором доступного отдела, «Я отправил»,
  «Назначено мне», «Ждут моего ответа»; уведомления и административные разделы
  сохранены, свёрнутая панель сохраняет иконки направлений.
- Доска: четыре активных стадии, отдельный архив, сводка, поиск по тексту/автору/
  отделу/заказу/телефону, категория, два уровня срочности. Свободного DnD нет.
- Карточка: центрированное окно до 740 px; один поток: статус и возраст,
  название, описание, автор/отдел/исполнитель/категория, данные претензии,
  действия, обсуждение. История свёрнута. Описание сначала читается; редактирование
  включается явно. Пустая загрузка файлов скрыта за действием добавления.
- RequestDialogProvider сохраняет страницу за карточкой. Существующие
  MyTaskCommandLoader/TaskCommandPanel загружают реальные данные и проверяют доступ
  заново при открытии. Смена сотрудника отменяет прежнее чтение.
- После отправки формы открывается созданное обращение. Повторы создания и
  отправки сохраняют прежние operationId.
- Светлая тема по умолчанию. Новый ключ `lenkanban-theme-v2` один раз исключает
  прежнюю сохранённую тёмную/системную тему; последующий ручной выбор сохраняется.

## Точки интеграции и проверки

Основные файлы: RequestBoardPresentation.tsx, RequestDialogProvider.tsx,
TaskDetailPanel.tsx, CreateTaskDialog.tsx, GlobalCreateRequest.tsx, страницы
главной и my-tasks, API request-directions/tasks, request-components.css и меню.
Персональные requestScope=mine/reply только сужают общую политику чтения:
канонический автор либо автор legacy заявки; ожидание ответа — соответствующему
автору. Выбор отдела использует общую политику создания.

`npm run test:ui:redesign`: 128 проверок настоящих компонентов, 4 варианта
desktop/mobile × light/dark, 16 axe AA-проверок без нарушений. Полный отчёт и
ограничения: `outputs/design/redesign-production-qa/REPORT.md`. Это изолированный
стенд с синтетическими HTTP/socket/session, без реальной БД, доставки уведомлений
и измерений VPS. Точный опубликованный commit, images и backup фиксируются
отдельно в deploy/PRODUCTION_STATE.md после фактической активации.
