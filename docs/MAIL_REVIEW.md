# Уточнение неразобранных почтовых тем

Уточняющий разбор относится к тем же заголовкам и видимым вступлениям выбранных страниц 1–100 за **01.01.2025–20.10.2026**. Он не расширяет охват почты и не означает прочтение полных обсуждений или вложений. Базовый срез: 1731 тема в периоде, 917 предварительных назначений и 814 неразобранных тем.

## Как фиксируется результат

Каждая из 814 тем получает локальный `review_id`, хеш исходного заголовка/вступления/даты и хеш корпуса для разметки. Приватная таблица сопоставления хранит исходные ID и ссылки. До объединения результатов проверяются полный снимок всех исходных тем, отсутствие пропусков/дубликатов, принадлежность исходному остатку, допустимые категории и совпадение хешей. Изменившийся источник требует нового базового среза: пересчитывать хеш поверх старых решений нельзя.

Первый просмотр распределён между двумя субагентами по 407 тем; отдельный субагент независимо просматривает все 814. Совпадение назначения принимается как предварительная классификация. Расхождения сохраняются без принудительного выбора, пока не выполнен локальный разбор. Для явно выявленных новых процессов допускается отдельное локальное уточнение прежнего `new_family_needed`. Оно учитывается отдельно от совпадений моделей. Исходные 917 назначений защищены от незаметной смены снимка, но не проходят повторную смысловую проверку в рамках этого этапа.

OpenCode Go был запрошен как обработчик всех 814 тем, но вернул `Go usage limit exceeded` (ограничение за 5 часов) до чтения корпуса: **обработано им 0 тем**. Повторы, переключение провайдера, изменение оплаты и платное превышение не выполнялись. Фактический разбор выполнен субагентами Codex. В отчёте это указано явно.

## Повторное построение отчёта

```powershell
node scripts/mail/review-unmatched.mjs --input .mail-work/iab-window-2025-2026 --review-dir .mail-work/unmatched-review-2026-10-20
```

Команда требует приватные `manifest.json`, `source-baseline.json`, `mapping.json`, `topics.ndjson`, `native-a.json`, `native-b.json`, `independent.json`, `go-status.json` и при наличии `adjudications.json`. Решения содержат только ID просмотра, хеш и фиксированные коды назначения/основания/уверенности. Произвольные цитаты и дополнительные поля отвергаются.

CLI возвращает 0 после полного проверенного учёта решений и выбранного диапазона страниц; 2 — при оставшихся расхождениях или неполном диапазоне; 1 — при некорректных/устаревших данных. Законно неразобранные темы с недостаточным контекстом не мешают завершить учёт: их нельзя искусственно назначать в доски ради нулевого остатка.

Файлы в локальной папке `result/`:

| Файл | Содержимое |
|---|---|
| `reviewed-overview.json` | Баланс, группы, актуальность, аудит двух просмотров и уточнений |
| `reviewed-overview.md` | Обезличенная сводка для публикации |
| `reviewed-topics.ndjson` | Текущее назначение каждой темы и исходная ссылка; только локально |
| `reviewed-unmatched.ndjson` | Новый остаток и причины; только локально |

Публичный результат публикуется в [итоговой сводке](MAIL_OVERVIEW_RESULTS_2026-10-20.md). Старый `overview/unmatched-overview.ndjson` остаётся исходным остатком 814 и не заменяет новый файл.

## Как выбираются доски

Разметка процесса не равна решению внедрить отдельную доску. Проверяются свежая активность, самостоятельное требуемое действие, участники, существующий инструмент и смысл стадий. Запрос на возврат внутри жалобы остаётся типом клиентского обращения; справочники и инструкции не превращаются в Kanban автоматически. Если процесс уже переведён в CRM, сначала проверяется интеграция и исключается дублирование.

Новые поля и стадии в `reviewed-taxonomy.mjs` — предложения шаблонов. Юридические запросы и рассрочки требуют ограниченного доступа; классификация не подтверждает правовые утверждения из писем и не принимает решений о людях или финансовом согласовании. Одна общая ветка может содержать множество случаев, а несколько веток — один процесс.

## Приватность и пределы

В Git не включаются исходные заголовки, тексты, контакты, авторы, исходные ID/ссылки, таблицы сопоставления, SQLite и записи решений. Публикуются только фиксированные определения процессов, агрегаты, код, синтетические тесты и ограничения.

Механическая редакция имён и контактов не гарантирует удаления чувствительных обстоятельств из текста. Перед любой будущей внешней обработкой корпус требует отдельной смысловой очистки: обнаружены фрагменты о здоровье/семье и метки учётных данных. Текущий корпус нельзя повторно отправлять внешнему обработчику по одному лишь успешному поиску телефонов и email. Лимит Go возник до чтения корпуса; в этом запуске эти данные Go не обрабатывал.

Согласие двух моделей не является измеренной точностью. Тема с активностью в 2026 не обязательно содержит незавершённую работу, а число тем не доказывает периодичность и не равно количеству карточек. Окончательные назначения и внедрение подтверждаются владельцами процессов.
