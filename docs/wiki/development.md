# Разработка и тестирование

Сверено с корневыми конфигурациями 20.10.2026. Команды ниже описывают назначение проверок; результаты нового прогона здесь не заявляются. Подготовка окружения и регистрация описаны в [LOCAL_SETUP.md](../../LOCAL_SETUP.md).

## Подготовка

Используйте Node.js 22.22.2+ ветки 22, npm, отдельную локальную PostgreSQL-базу и Mailpit. `.env.example` и `compose.local.yaml` присутствуют в корне. После настройки `.env` установите зависимости через `npm ci` и сгенерируйте Prisma Client через `npm run prisma:generate`. `db:push` разрешён в инструкции первого запуска только для новой пустой локальной базы; применение миграций к существующим данным требует отдельного плана. `db:reset` удаляет данные.

Разработка запускается двумя процессами из одного корня:

```sh
npm run dev -- --hostname localhost --port 3555
```

```sh
node --env-file=.env --import tsx src/socket/server.ts
```

Второй процесс нуждается в собственном окружении. `socket:dev` (`tsx watch`) и `socket:start` (`tsx`) не содержат флага загрузки `.env`. Для связки с real-time сохраняйте порт 3555: запрос проверки сессии в Socket.IO жёстко направлен на `localhost:3555`.

## Скрипты package.json

| Команда | Что делает |
| --- | --- |
| `npm run dev` | `next dev`; порт в локальной инструкции задаётся явно |
| `npm run build` | `next build` |
| `npm start` | `node server.js`; отдельный Socket.IO не запускает |
| `npm run lint` / `npm run lint:fix` | ESLint всего каталога / ESLint с изменением файлов |
| `npm run typecheck` | `tsc --noEmit` |
| `npm test` / `npm run test:watch` | Vitest однократно / в режиме наблюдения |
| `npm run test:unit` | Vitest только по фильтру `src/features` |
| `npm run test:integration` | Vitest по фильтру `tests/integration` |
| `npm run test:e2e` | Playwright согласно его конфигурации |
| `npm run test:e2e:ui` / `npm run test:e2e:headed` | Playwright UI / видимые браузеры |
| `npm run prisma:generate` | Генерация Prisma Client |
| `npm run db:push` | Прямое изменение схемы БД без генерации клиента |
| `npm run db:seed` | Создание/обновление демоданных |
| `npm run db:reset` | Разрушительный сброс, генерация клиента и seed |

`next.config.mjs` отключает ESLint внутри сборки (`ignoreDuringBuilds: true`). Успешная сборка не заменяет `lint`, тесты и ручную приёмку. `test:unit` — фильтр путей, а не гарантия запуска всех модульных тестов проекта.

## Vitest

`vitest.config.ts` задаёт проекты `node` и `jsdom`. В jsdom попадают `*.component.test.tsx` и `use-kanban-dnd.test.tsx`; остальные подходящие тесты обрабатывает node-проект, исключая `e2e/`. Общая подготовка — `src/test/setup.ts`.

В `tests/integration/` есть проверки чата и перемещений. Перед запуском изучите конкретный файл и его переменные окружения: название «integration» само по себе не гарантирует изоляцию от БД. Отдельные проверки могут пропускаться при отсутствии требуемых настроек; количество пропусков нужно фиксировать вместе с результатом.

В корне есть вложенная копия `lenkanban/`. `tsconfig.json` включает `**/*.ts` и `**/*.tsx`, ESLint запускается на `.`, а Vitest использует широкое обнаружение файлов. Явного общего исключения этой копии в конфигурациях нет. Поэтому не интерпретируйте удвоенные тесты или ошибки вложенных файлов как независимое подтверждение одной рабочей копии; сначала определите, какой набор файлов проверяется. Документирование не изменяло эти настройки и не удаляло копии.

## Playwright и тестовые данные

`playwright.config.ts` по умолчанию выбирает только `kanban-dnd-v2.spec.cjs` и `kanban-theme-accessibility.spec.cjs`. Остальные файлы `e2e/` не входят в этот запуск автоматически. Настроены Chromium, Firefox, WebKit, Pixel 7 и iPhone 13; последние два проекта — браузерные профили эмуляции, а не реальные устройства. Один worker, повторы в CI — два.

До запуска:

1. Подготовьте отдельную PostgreSQL-базу, имя которой заканчивается ровно на `_test`, и совместимую схему. `kanban_local` из Compose по умолчанию не подходит.
2. Задайте `E2E_DATABASE_URL` в окружении процесса. Конфигурация требует её даже при `PLAYWRIGHT_EXTERNAL_SERVER=1`; одного значения в `.env` может быть недостаточно, поскольку конфигурация не содержит его явной загрузки.
3. Установите нужные браузеры (`npx playwright install`) и проверьте требования выбранных сценариев и фикстур.
4. Запустите `npm run test:e2e`. По умолчанию Playwright сам поднимает dev-сервер с точным origin `http://127.0.0.1:3555` и не переиспользует существующий сервер. Предварительно освободите этот порт.

Проверки URL/БД находятся в `e2e/fixtures/safety.cjs`. Исторический рабочий домен и его поддомены блокируются; управляемый сервер требует точного origin выше. Для внешнего тестового сервера задаются `PLAYWRIGHT_EXTERNAL_SERVER=1` и `PLAYWRIGHT_BASE_URL`, но необходимо самостоятельно обеспечить, что сервер и фикстуры используют одну выделенную тестовую БД. Суффикс `_test` — только проверка имени, а не доказательство изоляции инфраструктуры.

`E2E_NEXTAUTH_SECRET` необязателен: конфигурация создаёт случайный секрет для своего сервера. Не используйте рабочие учётные данные. Отчёт Playwright, скриншоты, видео и трассы могут содержать тестовые данные; публикуйте их только после проверки содержимого.

## Минимальная ручная приёмка

- Вход, выход, подтверждение email; права владельца, участника и постороннего пользователя.
- Создание и редактирование задачи, повторное открытие после сохранения; черновик после перезагрузки и офлайн.
- Перемещения между колонками и карточками, автопрокрутка, отмена, клавиатура, две сессии и переподключение.
- Таблица, календарь и фильтры; чат, метаданные вложений, уведомления.
- Светлая/тёмная тема, узкий экран, фокус и доступные названия элементов.

Изменяющие данные сценарии выполняйте в выделенном тестовом проекте. Фиксируйте команду, дату, среду, результат, пропуски и оставшиеся ограничения. Исторические отчёты в каталоге документации подтверждают только заявленный там контекст и дату; они не заменяют свежий запуск из текущего снимка.
