## Технические проверки

1. **Повторяющиеся задачи.** `/api/recurring-tasks/process` проверяет bearer только при заданном `CRON_SECRET`; закрыть режим без секрета до эксплуатации. Подтвердить запуск cron, поведение параллельных вызовов и повтор после сбоя без дублей.
2. **Safe Browsing.** Уточнить состояние исторически зафиксированного предупреждения и доказательства из Search Console. [Порядок](security.md). Инцидент не считается закрытым по HTTP 200.
3. **Подтверждение почты.** Проверить доставку, истёкший и повторно использованный токен, гонки, повторное открытие и безопасные журналы.
4. **Доступ и конкурентность.** Два участника перемещают одну/разные карточки; проверить версии, повторы запросов, оба DnD-адаптера, потерю сети и изоляцию проектов.
5. **Чат и уведомления.** Проверить повтор отправки, переподключение, прочтение, адресатов, ссылки и локальные черновики без потери текста.
6. **Визуальная регрессия и доступность.** Обе темы, узкие размеры, модальные окна, ошибки, русские объявления DnD вместо ID в legacy-адаптере.
7. **Воспроизводимость.** Проверить установку на отдельной БД по [LOCAL_SETUP.md](../../LOCAL_SETUP.md), миграции, сборку и подходящие тесты; записать фактический результат с датой.

## Учёт работ

Целевой приватный GitHub — `lenremont2/kanban_pochta`; локальная копия без `.git`. Наличие issue — постановка задачи, а не её выполнение. Закрывать задачу после реализации, проверки критериев и ссылки на доказательства. Публикацию исходников, выпуск и импорт учитывать отдельно.

Рабочий цикл: воспроизведение/критерии → изменение → подходящие проверки → ревью → выпуск с откатом → проверка в целевом окружении. Исторические аудиты сохраняют исходные даты и не заменяют новый прогон.
