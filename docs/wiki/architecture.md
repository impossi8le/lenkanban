## Данные и права

`Project` принадлежит `ownerId`, участники задаются `ProjectMember`. Глобальные роли: `USER`, `ADMIN`; роли участника: `MEMBER`, `PROJECT_ADMIN`. Проверка доступа (`../../src/lib/project-access.ts`; исходник/артефакт не входит в публикацию) разрешает участникам чтение/запись, администраторам проекта — также управление участниками; владельцу и глобальному администратору — все эти действия. Корректность применения проверок во всех endpoint требует отдельной регрессии.

`ProjectColumn` задаёт колонки и `workflowKey`. `Task` хранит `columnId`, legacy `status`, приоритет, срок, описание, вложения JSON, позицию, `rank` и `version`. Связанные модели: `TaskAssignee`, `Tag`/`TaskTag`, `TaskChecklistItem`, `Activity`, `ChatMessage`. У задачи допускается несколько исполнителей; отдельного поля единственного владельца бизнес-передачи нет.

## Доска, карточки и real-time

В исходниках есть доска, таблица, календарь, сохранённые представления, задачи, вложения и чек-листы. API перемещения `/api/tasks/:id/move` принимает колонку назначения, соседние карточки, ожидаемую версию и UUID операции; использует `TaskMoveOperation` и ревизию доски. Конфликт версии возвращает 409. Legacy и новый DnD-адаптер сосуществуют; выбор зависит от `dndV2Enabled`. Проверять нужно оба. [Исторический дизайн](../superpowers/specs/2026-07-28-kanban-dnd-modernization-design.md).

HTTP-ответ подтверждает запись, Socket.IO доставляет обновления. При приёмке сверять состояние после перезагрузки и во второй сессии. Название карточки сохраняется автоматически при обычном вводе, описание — явно. Восстановленное из черновика название требует подтверждения. Черновики привязаны к пользователю/задаче и браузеру; очистка данных браузера удаляет их. [Черновики](../TASK_DRAFTS_2026-09-15.md), [статус сохранения](../TITLE_SAVE_STATUS_2026-09-15.md).

## Шаблоны, расписания и правила

| Область | Модели и код | Ограничение проверки |
| --- | --- | --- |
| Шаблоны задач | `TaskTemplate`, `src/app/api/templates`, `src/components/templates` | Применение и сохранность полей не проверены сегодня |
| Шаблоны проектов | `ProjectTemplate`, `src/app/api/project-templates`, `src/components/project-templates` | Создание проекта из шаблона требует приёмки |
| Повторения | `RecurringTask`, `src/app/api/recurring-tasks`, `src/components/recurring` | Нужен внешний вызов процессора; cron неизвестен |
| Автоматизации | `AutomationRule`, `src/lib/automation-processor.ts`, `src/components/automation` | Проверить конкретные события, условия и действия |
| Уведомления | `Notification`, `src/lib/notifications.ts`, `src/lib/notification-triggers.ts`, API `notifications` | Наличие модели не подтверждает доставку |
| Представления | `SavedView`, API `saved-views`, `src/components/saved-views` | Проверить фильтры и права |

Действия процессора автоматизаций: уведомление исполнителей/создателя, добавление/удаление тега, смена приоритета, назначение пользователя, перемещение и комментарий.

`POST /api/recurring-tasks/process` создаёт задачи из наступивших повторений. Проверка bearer в handler выполняется только при заданном `CRON_SECRET`; отсутствие секрета не отклоняется, а middleware исключает API. Это открытый пункт до эксплуатации, вместе с проверкой параллельных запусков и повторов после сбоя.

## Границы переноса basemail

[Почтовый backlog](../KANBAN_MAIL_BACKLOG.md) описывает будущие процессы, а не готовую интеграцию. Поиск по `src`/`prisma` не обнаружил выделенного basemail/IMAP-импортера или моделей отчётов, чеков и лидов. `Task` можно рассматривать как основу, но правила периода, отдельной операции, единственного ответственного и подтверждения передачи ещё требуется определить.

Целевые единицы работы: сотрудник + период для отчёта; запрос клиента на отправку чека; один лид с ответственным и принятием продажами. После таймаута прочитаны заголовки и начала 40 тем; полный архив не исследован. Схемы предварительные. «ЧЕКИ 2026» не является подтверждённым процессом учёта расходов. [Новые требования LDAP, подразделений и ограничений видимости](../ORG_ACCESS_MAIL_ROADMAP.md) пока не реализованы. Реальные тексты, контакты и вложения в документацию не копировать.
