# Визуальная приёмка #60 · 24.10.2026

Решение root в рамках разрешённых пользователем уточнений: использовать явно ограниченный бюджет измеренной вариации пикселей. Это политика приёмки, а не исправление CSS и не установленная причина расхождения. Критерии #60 требуют объяснить пороги; строгого равенства каждого raw-пикселя они не устанавливают.

## Обязательные условия

Сохраняются каноническая закреплённая среда, проверка browser/OS/архитектуры/Playwright, происхождения PNG, viewport, locale, timezone и времени. Windows и Linux не становятся взаимозаменяемыми. Полная матрица — 360/768/1440 × light/dark/system-light/system-dark, применимые экраны и состояния. Проверки overflow, геометрии, доступности важных контролов, keyboard, axe и contrast не ослабляются. Маски, скрытие функциональных зон, размытие, изменение размера или цветовая нормализация для прохождения сравнения запрещены.

`capture` сохраняет `expect(page).toHaveScreenshot`. Для него явно заданы `threshold: 0.02`, `maxDiffPixels: 0`, `maxDiffPixelRatio: 0`, fullPage, отключённые анимации, скрытый caret и CSS scale. После этого дополнительный PNG Buffer проходит **оба** сравнения с тем же эталоном:

1. `expect(buffer).toMatchSnapshot` с теми же perceptual-порогами.
2. Проверка всех декодированных пикселей: точные размеры; alpha каждого пикселя совпадает; изменены не более 64 RGB-пикселей; максимальная абсолютная разница любого RGB-канала не более 4 из 255.

Оба дополнительных gate проверяют одни и те же байты. Успешный `toHaveScreenshot` сам не возвращает actual PNG; нельзя объявлять отдельные снимки одним кадром. Допустимы только 8-bit RGB/RGBA PNG без ICC-профиля, RGB имеет alpha 255. Наличие ICC-профиля в любом входе — FAIL, даже при одинаковых закодированных RGB. Декодер дополнительно использует `ignoreIcc: true`: цветовой профиль не должен преобразовать исходные каналы и скрыть различие. Ошибка декодирования или несовпадение размеров — FAIL. Бюджет абсолютный, не увеличивается с размером экрана и не выделяется отдельно каждому компоненту.

При отказе сохраняются expected, actual, видимый magenta diff и JSON с количеством изменённых пикселей, максимальными RGB/alpha delta, bbox, политикой и SHA256 обоих PNG. Ошибка декодирования также даёт FAIL и видимый диагностический PNG. Статистика прикладывается и при успешной обычной проверке. Режим обновления эталонов остаётся отдельным явным действием существующего harness; обычный CI эталоны не пишет. SHA256 sidecar вычисляется после последней принятой записи PNG. Новые sidecar содержат версию и параметры pixel policy.

## Обоснование и пределы

Историческая измеренная пара Linux: 42 изменённых raw-пикселя с максимумом RGB delta 4. Свежая пара Linux: 28 пикселей с максимумом 2. Вторая инструментированная страница подтвердила неизменность стилей/геометрии границы, но не установила причину вариации между контейнерами; отдельно наблюдался один меняющийся пиксель вне header. Не называть эту вариацию доказанным antialiasing, проблемой шрифта или GPU.

Порог 64/4 покрывает эти наблюдения и ограничивает принятый риск. Он может пропустить небольшое слабоконтрастное изменение границы, глифа или индикатора в пределах бюджета. Поэтому нельзя обещать отказ при абсолютно любом изменении UI или любом сдвиге на один пиксель. Изменение alpha на 1, RGB на 5 в одном пикселе, 65 слабых изменённых пикселей и широкое изменение цвета должны отвергаться. Функциональные и accessibility-проверки остаются самостоятельными обязательными условиями.

## Проверки реализации

```text
node --test e2e/fixtures/visual-pixel-budget.test.cjs e2e/fixtures/visual-capture.test.cjs
```

Тесты проверяют границы бюджета, несовпадение размеров, alpha, повреждённый PNG, реальное PNG-смещение контрастной линии, инверсию и широкое изменение на один оттенок, которое отдельно пропускает perceptual comparator. Проверяется передача одного Buffer обоим gate, сохранение всех артефактов при отказе/setup и финальный hash при ручном обновлении. Эти проверки используют реальные декодирование/кодирование PNG, но не проверяют браузер или БД.

После изменения harness нужны actual narrow compare в канонической среде, полная матрица, осознанный review эталонов и намеренная UI-мутация с ожидаемым FAIL. Успех unit-тестов и принятие измеренных старых пар не закрывают #60 и не подтверждают production.
