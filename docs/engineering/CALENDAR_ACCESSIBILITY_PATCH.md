# Локальный accessibility-патч react-big-calendar

Владелец интеграции — календарь Ленканбана. Зависимость закреплена на 1.19.4.
Патч исправляет структуру table/rowgroup/row/cell в Month и заголовках Day/Week,
а также доступ клавиатуры к пустой прокручиваемой временной сетке. Он не делает
весь календарь интерактивным grid и не меняет маршруты, даты или права задач.

`scripts/patches/react-big-calendar-1.19.4-a11y.json` хранит происхождение,
точные исходные/итоговые SHA256 и изменения восьми CJS-модулей и ESM bundle.
Исходный MIT LICENSE пакета сохраняется и проверяется по SHA256.

Обычный `npm ci` запускает `scripts/patch-react-big-calendar.mjs --apply`.
Перед первым изменением проверяются все файлы, версия, package metadata,
лицензия и итоговые байты. Повторный запуск ничего не меняет. Неизвестные
байты или частично применённый патч отклоняются; требуется чистая установка
проверенного lock. `npm run build` отдельно выполняет `--verify`, поэтому
установка с отключёнными lifecycle scripts не даёт незаметно собрать старые
семантические ошибки. Docker deps копирует оба install-входа до `npm ci`.

В приложении публичный `eventWrapper` передаёт тип date/time через React
context без дополнительного DOM. Date/all-day/Agenda сохраняют native button;
timed-событие использует единственную кнопку vendor wrapper. Enter/Space
не создают двойного открытия, а закрытие карточки возвращает фокус opener.

Проверка механизма установки: `node --test scripts/patch-react-big-calendar.node-test.mjs`.
Это Node test, отдельно от Vitest. Browser-проверки должны сохранять полный
axe, темы, оба порядка CSS, пустые/обычные/all-day/midnight/multi-day события,
overflow с настоящим drilldown и активацию мышью/Enter/Space. Optional resource
grouping приложением не используется и отдельной приёмки не имеет.

Перед обновлением зависимости проверить upstream и заново принять обе
дистрибуции и приложение. Нельзя менять только ожидаемые SHA или отключать
verify для прохождения установки. Для новой версии отдельно проверить роли
Month/Day/Week и отсутствие вложенных кнопок в обеих дистрибуциях. Принятие
обновления требует свежих browser-проверок; номер версии сам по себе их не заменяет.

Фактические результаты combined build, browser и release acceptance фиксируются
отдельно в BOARD_COMPLETION_2026-10-24.md. Синтетический probe не заменяет
проверку собранного приложения или production.
