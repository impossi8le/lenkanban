Использовать общий RequestBoardPresentation: стандартный заголовок и кнопку создания, показатели доступных обращений, «Текущие обращения / Архив», «Список / Доска», поиск, срочность и категорию. Для безнала сохраняются три согласованные визуальные колонки, прежняя форма с общими полями и необязательными реквизитами. Новую параллельную реализацию доски не создавать.

Одинаковое оформление не меняет права: заявитель видит только разрешённые общим actor-scoped механизмом заявки (в том числе свои). Полная доска, metadata, project-room и исполнение не открываются через canCreate. Группа остаётся пустой до решения владельца; роли, отделы и request.execute не назначаются ради отображения интерфейса.

Данные загружаются существующим tasks API с общей проверкой прав; открытие карточки и создание используют прежние dialogs. При отказе или отзыве доступа прежние данные не должны оставаться на экране. Полнота счётчиков/пагинация и обновление при возврате фокуса проверяются явно. Не подписывать заявителя на закрытую комнату проекта.
