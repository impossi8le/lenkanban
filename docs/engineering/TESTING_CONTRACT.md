## Границы запуска

Использовать корневые `package.json` и конфигурации. Вложенная `lenkanban/` — самостоятельная копия неизвестного происхождения: не исполнять её тесты и не смешивать её исходники с корневыми. Корневые Vitest, TypeScript и ESLint исключают эту папку. Не удалять копию ради зелёных проверок.

Обычные unit/component/route-тесты не подключаются к БД, SMTP, S3, Sentry или внешнему API. Зависимости должны быть подменены до импорта модуля с побочными эффектами; сбрасывать мок и состояние после каждого сценария. Не мокировать сам проверяемый алгоритм. Подмена Prisma в route-тесте проверяет контракт обработчика, а не SQL, транзакционную изоляцию или фактическую видимость данных.

## Слои и доказательства

Integration-файлы запускаются последовательно (`test:integration` задаёт `--no-file-parallelism`): они используют общий singleton версии организации. Параллельный запуск независимых файлов создаёт посторонние CAS/Serializable-конфликты между фикстурами. Конкурентные транзакции внутри отдельных тестов сохраняются; отключать их нельзя. На изолированной acceptance-БД 23.10.2026 последовательный прогон дал 110 passed / 0 failed / 0 skipped в 18 файлах; первоначальный параллельный прогон дал 102 passed / 8 failed и сохранён отдельно, а не объявлен успешным.

## Изоляция БД и внешних эффектов

1. Unit-прогон выполняется с пустыми `TEST_DATABASE_URL` и `E2E_DATABASE_URL`; интеграционные сценарии тогда отмечаются skipped. Не переносить туда `DATABASE_URL` из приложения.
2. До запуска интеграции явно подтвердить отдельный тестовый кластер/БД и пользователя с правами только на тестовую область. Запрещено использовать production. Не выводить URL или секреты в отчёт. Текущие integration guards требуют `_test` в имени и другой hostname, чем `DATABASE_URL`/`PRODUCTION_DATABASE_URL`; это защита, но не доказательство происхождения БД.
3. Для новых shared guards использовать точный суффикс `_test`, PostgreSQL protocol и один сегмент имени; guard проверяется до создания PrismaClient. Существующие различия между integration guards и `e2e/fixtures/safety.cjs` — долг унификации, а не повод ослаблять проверку.
4. Данные создавать с уникальным runId и синтетическими адресами `.invalid`; чистить только ID и marker текущего прогона. Глобальные delete/reset/seed не являются проверкой. Провал cleanup — провал прогона; дождаться фоновых уведомлений до очистки.
5. E2E требуют `E2E_DATABASE_URL` с точным суффиксом `_test`. Управляемый Playwright сервер работает только на `http://127.0.0.1:3555`, не переиспользует уже запущенный сервер. `PLAYWRIGHT_EXTERNAL_SERVER=1` допустим только для отдельно проверенного тестового стенда с той же БД; обходить guard ради запуска нельзя.
6. SMTP/S3/аналитику подменять локальными sink/stub. Контрактный тест не отправляет реальные письма и не загружает файлы в рабочий bucket. Реальный SSO проверять отдельно по согласованному контракту; локальный парольный вход не объявлять проверкой корпоративного SSO.

## Общая регрессия lifecycle и прав

Канонический набор следует 12 сценариям `REQUEST_LIFECYCLE.md:101`. Не закреплять старый произвольный DnD как разрешённый новый бизнес-переход.

- Черновик → отправка: приватность черновика, одна отправленная заявка и один набор уведомлений при повторе.
- Одновременное взятие в работу: ровно один исполнитель, проигравший получает актуальное состояние; доказать перекрытие транзакций, а не только вызвать `Promise.all`.
- Уточнение: обычный комментарий не меняет статус; ответ с комментарием/файлом возвращает в работу; пустой ответ запрещён, повтор не дублирует историю/уведомления. Два интервала ожидания корректно приостанавливают срок.
- Завершение и переоткрытие с причиной; недоступный прежний исполнитель возвращает заявку группе. Автор отменяет до работы; после начала прямой запрос автора отклоняется.
- Матрица акторов: автор, один исполнитель, наблюдатель, ответственная группа, руководитель настроенной области, администратор подразделения, глобальный администратор, посторонний и пользователь без сессии. Проверить совмещение ролей и отзыв доступа при уже открытой сессии.
- Обычная/внутренняя часть: закрыты текст, файл, activity, realtime и уведомления; запрет должен работать и по прямому API/URL. Наблюдатель комментирует и прикладывает файлы, но не меняет статус, описание и исполнителя.
- Междосочный перенос запрещён в одиночном/массовом API, UI, шаблонах и автоматизациях. Ошибочная доска — отдельное разрешённое удаление и новый черновик без старой внутренней истории.

Для каждого серверного запрета проверять отсутствие записи в БД, activity и отправки событий. Проверка скрытой кнопки сама по себе недостаточна.

## Диагностика и аналитика (#57–#59)

Schema validation проверяет допустимое имя события и whitelist полей; негативные сценарии включают токены, cookie, пароли, тексты заявок/сообщений, вложенные объекты и слишком длинный ввод. Проверить очистку на каждой фактической границе отправки, включая ошибку/redaction failure. Ожидаемый безопасный payload задаётся явно; snapshot всего объекта не заменяет проверки отсутствия чувствительного поля.

Корреляция проверяется от одного UI-действия через HTTP и серверную ошибку: связанные идентификаторы сохраняются, независимые действия не сливаются; retry не дублирует бизнес-эффект. Матрица включает отказ доступа, валидацию, конфликт версии, timeout/потерю сети и неожиданный 500. Stub приёмника подтверждает безопасные события и отсутствие реальной отправки. По согласованию пользователя доступ к аналитике имеют только глобальные администраторы; подробные события хранятся 30 дней. Проверить отказ остальным ролям, граничное время удаления и отсутствие скрытых payload в обычных уведомлениях.

## Визуальная проверка (#60)

Проверять светлую/тёмную/системную тему, desktop/tablet/mobile, клавиатуру, focus и scroll; DnD имеет доступную альтернативу. Фиксировать версию браузера/ОС, viewport, timezone, locale, шрифты, данные, анимации и часы. Эталон менять только после просмотра diff и принятия ожидаемого результата; автоматическое обновление эталона не исправляет дефект.

Существующий `kanban-theme-accessibility.spec.cjs` сохраняет скриншоты, измеряет контраст и запускает axe. Прикреплённый скриншот сам по себе не доказывает прохождение сравнения с эталоном; постоянную snapshot-регрессию и пороги добавлять отдельным изменением #60. Playwright сейчас выбирает только DnD и theme/accessibility spec, поэтому `npm run test:e2e` не означает покрытие всех файлов `e2e/` или всего lifecycle.
