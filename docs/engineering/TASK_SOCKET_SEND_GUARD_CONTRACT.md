# Task socket message:send guard — следующий срез

21.10.2026. Контракт подготовлен после независимого root source scout; ещё не реализация. Перед кодом сверить live владельцев #46/другого чата. Один владелец `src/socket/server.ts` и соответствующих tests; shared Task helper/schema только reuse. `setup.js` требует отдельного inventory и не считается закрытым этим срезом. Package/PM2 scripts указывают server.ts; это не доказательство работающего deployment.

Сохранить send schema/auth, clientId unique replay, public-author DTO, mentions/attachments/readBy и requester-only canonical duplicate delivery. В текущем server.ts message:send rate limiter не подтверждён; не описывать его как существующую защиту и не добавлять новую rate policy incidental-правкой. Legacy socket policy — только actual owner/member; global ADMIN сам по себе не расширяет доступ. Поэтому использовать существующий server-only `requireOwnerOrMember:true` в общем prepareLegacyTaskScalarBatch, не default ADMIN bypass. Actor/fresh policy проверяются в locked transaction.

До duplicate lookup/replay и до insert общий preflight Project→Task→freshactor SHARE/access→marker. Никакой old receipt/message replay до fresh authority/marker. Полученный Task identity и текущий author supplies сохраняются внутри разрешённой транзакции. Отсутствующие/marked/malformed/storage данные не fallback. Закрытые ACK: прежние outer TaskNotFound/AccessDenied/UserNotFound/ClientIdConflict сохранить; common NotFound после lockwait →TaskNotFound (не раскрывает revocation/actor); TaskCommandError →MutationRejected; неизвестный storage →InternalError. Без marker полей/raw exception или частичного успешного ACK.

Успешный insert и canonical duplicate — разные результаты. Только автор нового insert broadcast/notify; duplicate возвращается одному requester с исходной Task/author/clientId проверкой. Если вставка получила P2002, сначала полностью выйти из failed transaction, затем новая guarded transaction для canonical lookup; не читать в aborted PostgreSQL transaction. Не обещать exactly-once доставку/новый receipt/автоповтор и не вводить второй history/engine.

После commit delivery/logger failure не меняют committed ACK на failure и не подавляют независимые эффекты. Broadcast/notification используют захваченные разрешённые identity/DTO, не raw caller projection. Эти room emissions ещё не доказывают revocation/private isolation; до privateDRAFT/OWN/internal нужны все каналы. Ни marked rows, ни guessed legacy author/executor/status, ни schema/backfill.

Acceptance actual socket handler/common helper doubles: all6states/admin/malformed/storage before replay/create/effects; owner/member-only ADMIN bounds; revoke после ожидания parent lock; Task/author/clientId conflict; duplicate canonical requester-only/no повторных effect; P2002 guarded reread после unwind; commit/late delivery ACK; public author projection; прежние send/typing/reaction tests сохранены по своему поведению. Existing @prisma/client mock должен сохранить runtime Prisma export для настоящего shared helper; добавить tx delegates/projection, не обходить guard и не ослаблять прежние assertions. PostgreSQL concurrency/unique race не объявлять по fake storage. edit/delete/react, joins/typing/read-state/setup.js остаются следующими границами, отдельно сохраняется Project→Task→actor→ChatMessage lock order.
