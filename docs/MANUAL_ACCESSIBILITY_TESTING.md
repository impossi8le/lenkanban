# Ручная проверка доступности

Актуализировано по исходникам 20.10.2026. Это протокол будущей проверки, а не сертификат WCAG и не отчёт об успешном браузерном прогоне. Результаты аудитов марта и сентября относятся к их датам.

## Стенд и запись результатов

Использовать локальный тестовый стенд с отдельным проектом. Изменения задач выполнять только на тестовых данных. Для каждого сценария записывать commit, дату, браузер/ОС, экранный диктор, тему, viewport, результат, screenshot и шаги воспроизведения. Не включать пароли, токены и персональные данные.

Автоматизированный набор, ограничения его запуска и fixture — [TESTING_KANBAN_DND_V2.md](TESTING_KANBAN_DND_V2.md). Он проверяет только часть экранов. Axe без serious/critical нарушений не доказывает доступность всего продукта.

## Последовательность

1. Клавиатурой пройти вход, регистрацию, восстановление, проекты, доску, таблицу, календарь и карточку задачи. Проверить порядок Tab/Shift+Tab, видимый focus, доступные названия icon buttons, работу Enter/Space и отсутствие ловушки фокуса.
2. Проверить skip link к `#main-content` на страницах с соответствующим landmark. Корневой layout задаёт `lang="ru"` и саму ссылку; наличие кода не заменяет проверку фактического перехода.
3. Открыть и закрыть диалоги, меню перемещения, popover уведомлений и мобильную навигацию. Проверить Escape, начальный фокус и возврат к trigger; фон не должен оставаться доступным при модальном диалоге.
4. Проверить подписи и ошибки форм: label, обязательность, чтение ошибки диктором, сохранение введённых данных и отсутствие опоры только на цвет.
5. На доске отдельно проверить legacy и v2 (`Project.dndV2Enabled`). Найти drag handle, прочитать инструкции, активировать клавиатурное перемещение, проверить стрелки, завершение и Escape согласно подсказке адаптера. После reload проверить сохранённый порядок. Проверить альтернативное меню перемещения, пустую колонку и возврат фокуса.
6. Для v2 проверить блокировку drag при активном фильтре или сортировке не по позиции, откат после 409/сетевой ошибки и понятное сообщение. Ошибки моделировать только на тестовом стенде.
7. В NVDA + Firefox и VoiceOver + Safari проверить русские live announcements: начало, перемещение, завершение, отмена, ошибка. Проверить чтение заголовков колонок, приоритета, исполнителей и меню.
8. Повторить light/dark/system, масштаб 200% и узкий экран 390×844. Проверить отсутствие потери кнопок, обрезанного текста и перекрытия фокуса. В system изменить системную тему без повторного выбора меню.
9. Проверить контраст реально отрисованных поверхностей, градиентов и прозрачных наложений: обычный текст 4.5:1, крупный 3:1, значимые границы/индикаторы 3:1. Цвет приоритета должен сопровождаться текстом. Не переносить результаты token-теста на весь DOM.
10. Включить reduced motion в ОС; проверить отсутствие лишнего движения и сохранение обратной связи. Код использует `MotionConfig reducedMotion="user"` и CSS media query, но оба DnD-адаптера требуют ручной проверки.
