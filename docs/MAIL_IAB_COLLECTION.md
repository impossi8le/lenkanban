# Сбор через встроенный браузер

Когда отдельный Chrome не открывает почту, авторизованный встроенный браузер читает страницы сайта через разрешённый интерфейс управления браузером. Сбор использует открытый пользователем аккаунт и его фактические права. `scripts/mail/iab-store.mjs` сохраняет извлечённые страницы локально; сам модуль не открывает сайт и не выполняет сетевые запросы.

Данные текущего обхода находятся в `.mail-work/iab-full-2026-10-20/`. Каталог исключён из Git: тела сообщений, авторы, ссылки на вложения и профиль авторизации не публикуются. Публиковать можно код и отчёт без персональных данных после проверки его содержания.

## Что сохраняется

`mail.sqlite` — основное хранилище SQLite. Node.js 24 предоставляет встроенный `node:sqlite`, дополнительные серверы и Docker для этого хранилища не нужны. Режим WAL и `synchronous=FULL` обеспечивают фиксацию каждой страницы отдельной транзакцией. Повторное открытие того же каталога восстанавливает очередь. Повторный импорт страницы не создаёт копии сообщений.

Таблицы:

| Таблица | Назначение |
| --- | --- |
| `pages` | Очередь страниц списка и обсуждений, статус обработки, проверка ответа |
| `topics` | Заголовки, исходные ссылки, счётчики и доступные фрагменты списка |
| `messages` | Исходный ID сообщения, тема, текст, автор, дата и ссылки на вложения |
| `conflicts` | Новые версии при совпадении ID и различии содержимого; первая версия не перезаписывается |
| `failures` | Ошибки с кодом и страницей, без тела письма в журнале |
| `meta` | Неизменяемая область обхода, начало сбора, первое и последнее наблюдения счётчика |

Явный ID сообщения уникален в пределах источника. Если ID отсутствует, используется идентификатор по теме, адресу страницы и позиции; это ограничение отражается отдельным счётчиком и не считается надёжной идентификацией при изменении порядка сообщений. Одинаковый текст разных сообщений сам по себе не является основанием для удаления дубля.

Вложения пока сохраняются **как ссылки**, их файлы не скачиваются. Полноту архива вложений этот обход не подтверждает.

## Контракт сборщика

```js
import { openStore } from '../scripts/mail/iab-store.mjs';
const store = await openStore({
  dir: '.mail-work/iab-full-2026-10-20',
  scope: {
    url: 'https://mail.example.invalid/',
    folder: 'all',
    filter: 'all_topics',
  },
});
const next = store.nextListPage(); // { url, topic_id: null } либо null
// Страницу next.url читает отдельный контроллер встроенного браузера.
store.ingestListPage({
  url: next.url,
  topics: [/* { topic_id, title, source_url, message_count_hint, ... } */],
  page_links: [/* проверенные ссылки пагинации списка */],
  filter_confirmed: true,
  pagination_verified: true,
  observed_counter: { value: 52594, unit: 'unverified' },
});
await store.checkpoint();
store.close();
```

Это пример API, а не команда самостоятельного браузерного сбора. Пустая страница в примере намеренно не считается проверенной: для подтверждённого пустого результата требуется дополнительный `empty_verified: true`.

Для обсуждений `nextTopicPage()` возвращает следующую страницу с `topic_id`. `ingestTopicPage({topic_id, title, url, messages, page_links, pagination_verified, content_verified})` принимает сообщения в том же формате, что и основной сборщик. `source_message_id` должен быть ID записи сайта, а не номером в текущем массиве. Ссылки на страницы проверяются: разрешён только тот же origin, путь basemail и параметры просмотра; внешние ссылки и действия над письмами отклоняются. `page=1` нормализуется к первой странице.

Отсутствие подтверждения пагинации или содержимого отправляет страницу в `quarantined`; данные сохраняются, но успешное прохождение не засчитывается. Повтор одного и того же набора ID под другим адресом страницы также помещается в карантин: это может означать сброс фильтра, неверную пагинацию или изменение архива. `recordFailure({url,kind,topic_id,code})` фиксирует неудачу; `retryFailures()` возвращает ошибки и карантин в очередь. После исправления нужно повторно проверить страницу.

## Результаты и границы полноты

`progress()` возвращает отдельные количества обнаруженных тем, уникальных сообщений, пройденных страниц, ошибок, конфликтов и непроверенных страниц. `checkpoint()` атомарно записывает `manifest.json`; `exportNdjson()` потоково формирует `topics.ndjson`, `messages.ndjson`, `conflicts.ndjson` и обновляет манифест. Большой архив не загружается целиком в оперативную память при экспорте.

Первое и последнее наблюдения счётчика сохраняются раздельно. Число в интерфейсе нельзя приравнивать к сообщениям или темам до подтверждения единицы. Найденные темы также не равны прочитанным обсуждениям: каждая страница каждого обсуждения требует отдельного обхода.

При незавершённых страницах, карантине, ошибках или конфликтах статус покрытия — `partial`. Даже пустая очередь даёт `unverified`: живой почтовый архив может меняться во время обхода. Для заявления полного охвата нужна дополнительная проверка согласованности снимка и реального объёма источника. Тематический отчёт обязан показывать эти ограничения; невыгруженные сообщения не попадают в категорию «Неразобранное».

Проверка модуля: `node --test tests/mail/iab-store.test.mjs`. Тесты используют только синтетическую почту и временный локальный каталог.

## Пакетный обход через активную вкладку

`scripts/mail/iab-driver.mjs` предоставляет самодостаточные DOM-функции `readListDom()` и `readTopicDom()` и контроллер `collectBatch({tab, store, kind, maxPages, deadlineMs, getTopic})`. Его вызывают внутри активного сеанса управления встроенным браузером, передавая уже авторизованную вкладку Cua; самостоятельных сетевых запросов и извлечения авторизации модуль не делает. Пример одного пакета: `await collectBatch({tab, store, kind: 'list', maxPages: 5, deadlineMs: 40000})`. Все операции браузера и контрольные точки завершаются до возврата; незавершённые фоновые вызовы не поддерживаются. Ограничение времени проверяется между страницами: ожидание текущей страницы может завершиться позднее этого срока.

Контроллер ждёт фактические элементы страницы и проверяет URL, выбранный номер страницы и состояние «Скрыть все темы». Навигационный тайм-аут не означает потерю страницы, если после него подтверждено правильное содержимое. Для обсуждений передают `getTopic(topicId)` — функцию чтения сохранённых `title` и `message_count_hint`. Несовпадение числа сообщений на единственной странице с подсказкой источника помещает обсуждение в карантин; отсутствие тела сообщения также не считается успешным чтением. Это дополнительная проверка, а не доказательство согласованности всего архива. Пагинация извлекается из навигационных списков; ссылки внутри сообщений и ссылки создания письма исключаются. Проверка контроллера: `node --test tests/mail/iab-driver.test.mjs`.
