# Публикация доски и документации

Дата: 20.10.2026. Работа учитывается в [задаче #28](https://github.com/lenremont2/kanban_pochta/issues/28). После исправления прежнего результата задача повторно открыта и находится «В работе» до итоговой проверки. Этот документ не подтверждает её завершение.

## Рабочая доска

[Открыть «Ленканбан — реализация и развитие» в GitHub Projects](https://github.com/users/impossi8le/projects/6/views/1). Приватный проект принадлежит аккаунту `impossi8le` и содержит issues репозитория `lenremont2/kanban_pochta`. Поле Status карточки определяет её этап: «Заведена», «В работе», «На тестировании», «Завершена». Исходные задачи #1–#27 находятся в «Заведена»; #28 — «В работе» до итоговой проверки.

Представление, поля и автоматизации настраиваются в интерфейсе GitHub Projects и не хранятся как файлы репозитория. Документация, [инструкция](board/README.md), [регламент](TASK_WORKFLOW.md) и форма issue хранятся в Git. Старое собственное представление доски заменено нативным проектом; скачивание HTML, генерация JSON и синхронизация снимков больше не являются рабочим процессом.

## Состав документации

В репозитории сохраняются корневые Markdown-документы, каталог docs/ с историческими пометками, классификация 40 тем без исходных текстов и контактов, частичная openapi.yaml и форма issue. Исходники приложения, вложенная копия lenkanban/, .env, секреты, исходные письма и реальные вложения в эту публикацию не входят. Команды запуска описывают полный локальный снимок приложения.

Ссылки на отсутствующие в репозитории исходники и исторические артефакты записываются текстовыми путями. Локальные исходники не удаляются; публикация документации сохраняет историю репозитория.

## Автоматизации проекта

- Item closed переводит карточку в «Завершена». Закрывать issue разрешается только после успешных релевантных проверок и итогового комментария по регламенту.
- Auto-close issue срабатывает только для Status «Завершена». Перенос карточки в эту колонку выполняйте после приёмки результата.
- Автоматические переходы по привязке и слиянию PR отключены: сам факт PR не подтверждает тестирование и приёмку.

## Итоговая проверка

1. Открыть приватный проект и проверить четыре колонки Status, состав #1–#28 и соответствие карточек исходным issues без дубликатов.
2. Проверить переход «В работе» → «На тестировании» → «Завершена» на #28 только по мере появления фактических результатов; исходные продуктовые задачи не закрывать при создании доски.
3. Проверить настройки автоматизаций, доступность ссылок из README и регламента, удаление устаревшего собственного представления.
4. После публикации сверить состав и содержимое файлов Git с подготовленными документами; записать коммит, фактические шаги и результаты в #28.

На момент подготовки этих правок итоговая проверка ещё не завершена. Завершение #28 не означает внедрение LDAP, подразделений, бизнес-процессов или массового анализа почты: их критерии остаются в отдельных задачах.
