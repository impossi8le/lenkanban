# Реализация редизайна обращений — 25.10.2026

Этот файл описывает реальную реализацию в корне `D:/Lenkanban`. Автономный
`outputs/design/redesign-v1/index.html` остаётся демонстрацией с переключателем
ролей; production определяет роль по действующей сессии и серверным правам.

## Что реализовано

- Светлая тема по умолчанию, полная тёмная палитра; сохранён пользовательский выбор темы.
- Синяя левая панель сворачивается до иконок, выбор сохраняется локально. Мобильное меню сохранено.
- Раздел «Запросы в отделы», две карточки быстрого обращения на Главной.
- Красная кнопка «Добавить обращение», включая командную палитру.
- Карточки без коротких технических кодов и ручек переноса: автор, подразделение,
  возраст обращения, исполнитель либо ожидание специалиста, комментарии.
- «Взять в работу» появляется при наведении/фокусе; на touch видна постоянно.
  Доступность определяется общей политикой исполнения, команды повторно проверяют права на сервере.
- Ручной перенос карточек между столбцами отключён в рабочей доске.
- Два отображаемых уровня срочности. Старые CRITICAL/URGENT/HIGH отображаются как
  срочные, MEDIUM/LOW — как обычные; совместимые API enum не удалены.
- Форма претензии: категория, заказ, телефон, имя клиента, пожелание, описание,
  обычная ситуация/повышенный риск. Номер заказа ведёт в CRM. Чек-лист не добавлялся.
- Отдельная страница уведомлений, отметки прочтения, фильтр непрочитанных,
  настройка браузерного разрешения. Страница использует тот же actor-scoped
  query cache и API, что и существующий колокольчик. Второй socket/bridge не создаётся.

## Контракты и совместимость

Обращение создаётся как приватный DRAFT, после вложений отправляется канонической
командой submit. Операции создания и отправки повторяются с прежними UUID и
ожидаемой версией. Потеря подтверждения загрузки файлов не вызывает повторную
загрузку: пользователь продолжает отправку сохранённого обращения и проверяет
вложения в карточке. Восстановление результата загрузки не объявляется идемпотентным.

Маршрут: Новые → В работе → Ждём сотрудника / Решено → Закрыто, с действующими
правилами возврата, отмены и уточнения из REQUEST_LIFECYCLE. Внутренние enum и
workflowKey существующих столбцов не переименовываются. Неконфигурированная доска
отклоняет новую структурированную форму ДО создания записи, в том числе после
ожидания транзакционных блокировок. Старые заявки массово не конвертируются.

Поля формы сохраняются в существующем description в версионированном читаемом
блоке `Сведения об обращении (v1)`. Кодек — `src/lib/request-presentation.ts`.
Это не источник прав. Миграция схемы для этого релиза не требуется. Если позднее
нужны SQL-фильтры/отчёты по номеру заказа, выделить поля в схему отдельной
проверяемой миграцией; не пытаться считать текстовый префикс разрешением доступа.

## Настройка production

Явно запускаемый `scripts/provision-request-boards.ts` использует штатные
аудируемые команды организации для маршрута и создания отдела/группы/доски.
Он не вызывается при старте. Идентификаторы существующей техподдержки,
workflowKey, заявки и членство сохраняются; меняются её отображаемые названия.
Новая доска претензий получает существующих пользователей портала как MEMBER,
без административных прав или доступа к чужим обращениям.

В исходной production-конфигурации отсутствуют сотрудники отдела качества.
Создаётся пустая ответственная группа претензий: администраторам необходимо
назначить её реальный состав через существующее управление группами. Сотрудники
ИТ автоматически туда не включаются. До настройки обращение остаётся в ожидании.

## Скорость

Форма Главной загружается динамически при открытии. Карточки не делают отдельных
запросов за автором/исполнителем/правами. Проверка исполнительской возможности
выполняется на уровне доски; возраст обновляется одним общим таймером. Счётчики
Главной сгруппированы; существующие query cache, realtime и фоновые обновления
сохранены. Производственные показатели ответа сервера фиксируются отдельно от
изолированных визуальных проверок: последние не доказывают скорость БД/сети.
