## API: 30 проверок ожиданий

Машиночитаемая сырая запись исключена из публикации по #81; исторические результаты приведены ниже. Использован новый синтетический аккаунт `@example.test` и проект `AUDIT 20.10.2026`, отдельно от рабочего пользователя. Учётные данные/сессии не опубликованы; тестовые записи сохранены для продолжения.

| Группа | Наблюдение |
| --- | --- |
| Гость/вход | GET проектов без входа →401; регистрация→201, письмо получено в Mailpit, подтверждение→200; credentials callback→200 и сессия подтверждена |
| Проект/задача | Создан проект и четыре стандартные колонки; задача CRITICAL создана и прочитана, переименована, получена в списке |
| Перемещение | Canonical move→200, повтор того же operationId→200, новый operationId со старой версией→409; свежий GET подтвердил IN_PROGRESS и правильный columnId |
| Чек-лист/чат | Создание пункта→201 и чтение→200; создание сообщения→201 и чтение→200 |
| Страницы | `/my-tasks`, `/inbox`, `/messages`, `/analytics`, `/settings`, `/projects/:id/board`, `/projects/:id/tasks/:taskId` →200 |
| Подтверждение дефектов | `/projects/:id/table` и `/calendar` →404, POST `/api/uploads/direct`→404. Эти три PASS означают успешное воспроизведение отсутствующего функционала |
| Права | GET `/api/admin/users` обычным USER →404; контракт намеренно скрывает endpoint от не-ADMIN |

В первоначальном smoke ошибочно ожидался 403 для admin API, и последний шаг был записан FAIL. После чтения `src/app/api/admin/users/route.ts:28` ожидание исправлено на намеренный 404 и повторно проверено тем же аккаунтом. Сырая запись исходного запуска исключена из публикации по #81. Это ошибка ожидания проверки, а не дефект прав приложения.

HTTP 200 страницы подтверждает серверный ответ, но не работу всех контролов и гидратации. Canonical move API не равнозначен браузерному drag-and-drop. Ответ checklist/chat подтверждает HTTP-путь, но не доставку во второй клиент по Socket.IO. Смена значения версии при всех остальных путях записи не проверена.
