# PREFLIGHT — проверка VPS перед обновлением или первой установкой taskboard

**Перед следующим обновлением нужен свежий read-only preflight.** Этот раздел не является текущей SSH-проверкой. Историческая активация действующего production и его сохранённые настройки описаны в [PRODUCTION_STATE.md](PRODUCTION_STATE.md); отсутствие приложения на VPS не является условием обновления. Проверки выполняет уполномоченный оператор, результаты без секретов прикладываются к #70.

Выберите ветку: **обновление существующего стека** `/opt/taskboard`, Compose project `taskboard` (обычный следующий релиз), либо **первая установка** в действительно новом окружении. При обновлении сохраняются `.env.taskboard`, секреты, проект, DB/attachment volumes, nginx и cleanup timer. Не заменять рабочий env шаблоном, не запускать seed/reset или setup первого администратора.

Все команды — **только чтение**. Ни одна не меняет состояние. Если какая-то команда недоступна или нет требуемого доступа — зафиксируйте это как ограничение, а не как успех. Пустой фильтр/ненулевой exit не доказывает отсутствие ресурсов; не подменяйте ошибку доступа сообщением «свободно»/«отсутствует».

Исторический снимок: `Taskboard-taskboard.example.invalid/Taskboard-taskboard.example.invalid/SERVER-INVENTORY.txt`
от 20.10.2026. Он **не доказывает** текущее состояние: память, порты и контейнеры могли измениться.

## 1. Ресурсы и диск

```sh
free -h
df -h /
df -h /var/lib/docker
nproc
```

Ожидание: доступно памяти заметно больше, чем суммарные лимиты пакета
(app 768M + socket 384M + db 512M = 1664M). Если `available` меньше ~2 GiB —
**остановиться** и согласовать лимиты с владельцем до запуска. Отсутствие swap было зафиксировано исторически; проверьте текущий swap через `free -h`. При нехватке памяти возможен OOM-killer. Для обновления учитывайте также пиковые ресурсы backup/build и одновременных контейнеров.

## 2. Занятые порты

```sh
APP_PORT="${TASKBOARD_APP_PORT:-18766}"
SOCKET_PORT="${TASKBOARD_SOCKET_PORT:-18768}"
ss -lntp | grep -E ":($APP_PORT|$SOCKET_PORT|18765)\b"
ss -lntp
```

Значения выше — записанные app18766/socket18768, не доказательство текущего host env. До проверки оператор сверяет именно несекретные значения портов рабочего env; не выполнять `source .env.taskboard`, `cat` env или неотфильтрованный `docker inspect`/`compose config`. Compose fallback socket18767 отличается от записанного production18768 и обоих env examples; не откатывать порт к fallback при обновлении.

**Обновление:** слушатели на loopback ожидаются и должны принадлежать текущему taskboard/nginx upstream; занятый своим стеком порт не является конфликтом. **Первая установка:** выбранные app/socket порты должны быть свободны. 18765 зарезервирован MCP. Не менять порты автоматически; согласованная смена требует сверки существующего nginx upstream.

## 3. Контейнеры и чужие проекты

```sh
docker ps --format 'table {{.Names}}\t{{.Image}}\t{{.Status}}\t{{.Ports}}'
docker compose version
docker network ls
docker volume ls --filter name=taskboard --format '{{.Name}}'
```

**Обновление:** сверить существующие image ID, состояние и имена ресурсов проекта `taskboard`; `taskboard_pgdata`, `taskboard_attachments`, `taskboard_net` сохранить. Не создавать новый Compose project вместо рабочего. **Первая установка:** отсутствие одноимённых ресурсов проверяется до создания; при наличии выяснить владельца, не удалять. Список чужих контейнеров нужен как baseline и не должен измениться.

## 4. Каталог проекта

```sh
ls -ld /opt/taskboard
ls -l /opt/taskboard/compose.taskboard.yaml /opt/taskboard/.env.taskboard
ls -la /opt/mcp-isolated 2>/dev/null | head -5   # только чтение, не менять
```

**Обновление:** `/opt/taskboard` уже существует; проверить доступность ожидаемых файлов без чтения секретов, сохранить рабочие env/compose и данные по RUNBOOK_ACCEPTANCE. **Первая установка:** выбрать закрытый каталог без чужих данных; наличие старого стека требует отдельной сверки. Не использовать `/var/www` и не копировать оттуда старый kanban.

## 5. nginx: конфигурация и конфликты

```sh
nginx -v
nginx -t
sudo nginx -T 2>/dev/null | grep -nE "^[[:space:]]*(server_name|listen)[[:space:]]"
ls -la /etc/nginx/sites-enabled/
```

Ожидание: `nginx -t` — `syntax is ok` / `test is successful`. **Обновление:** существующий taskboard vhost и upstream сверить с loopback портами, не создавать дубликат. **Первая установка:** сначала выяснить назначение любого совпадающего vhost. Полный `nginx -T` не прикладывать к отчёту: выводить только необходимые несекретные директивы; upstream сверять локально оператором.

Версия nginx важна: шаблон использует `listen 443 ssl http2` (совместимо с 1.24 из
Ubuntu 24.04 и с 1.25+). Директиву `http2 on;` на 1.24 применять нельзя.

## 6. DNS

```sh
getent ahostsv4 taskboard.example.invalid
dig +short taskboard.example.invalid A
```

Ожидание: `DEPLOY_SERVER_IP` — адрес вашего сервера. `taskboard.example.invalid` — условный домен: замените его своим доменом. Перед изменениями проверьте существующую DNS-запись; не создавайте дубликат.
Наличие DNS не заменяет текущую проверку приложения и HTTPS.

## 7. Сертификаты

```sh
sudo certbot --version
sudo certbot plugins
sudo certbot certificates
```

Ожидание: nginx-плагин установлен; для существующего production сверить действующий сертификат, срок и имена, включая отдельно www. Использовать существующий сертификат, дубликат не выпускать. Отсутствие сертификата допустимо только как незавершённый этап первой установки; DNS не доказывает TLS.
Если nginx-плагина нет — **не обновлять весь сервер**, сообщить владельцу.
Standalone-режим с остановкой общего nginx запрещён.

## 8. Docker-демон

```sh
docker info --format '{{.ServerVersion}} {{.Driver}}'
docker system df
```

`docker system df` — только для оценки места. **Не запускать** `docker system prune`,
`docker image prune`, `docker volume prune` и любые глобальные очистки.
