# Локальная установка Ленканбана

Сверено с файлами корня `D:\Lenkanban` 20.10.2026. Это инструкция для изолированной разработки; новый запуск приложения, Docker и тестов в ходе документирования не выполнялся.

## Требования и выбор каталога

Используйте Node.js 22.22.2+ ветки 22, npm и Docker с Compose. Нижняя граница выбрана по `engines.node` пакета `jsdom` из текущего lockfile (`^22.22.2 || ^24.15.0 || >=26.0.0`); `package.json` собственного поля `engines` не задаёт. Интернет нужен для установки зависимостей и загрузки образов. Контейнеры обслуживают только PostgreSQL и Mailpit, Next.js и Socket.IO работают на хосте.

Откройте терминал в каталоге с `package.json`, `.env.example`, `src/` и `compose.local.yaml` — в этом рабочем пространстве это `D:\Lenkanban`. Вложенная `lenkanban/` содержит ещё одну копию; не переключайтесь между ними при выполнении шагов. Текущие широкие шаблоны проверок могут включать вложенные исходники, поэтому результат проверки всего каталога может отражать обе копии.

## Первый запуск

1. Скопируйте шаблон окружения в файл `.env`:

```powershell
Copy-Item .env.example .env
```

На macOS/Linux используйте `cp .env.example .env`. Если `.env` уже существует, сначала сохраните свои настройки: копирование может их заменить.

2. Сгенерируйте локальный секрет и запишите результат в `NEXTAUTH_SECRET` файла `.env`:

```sh
node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
```

3. Проверьте, что `DATABASE_URL` указывает на новую локальную базу Compose, а URL приложения и SMTP остаются локальными. Поднимите инфраструктуру и создайте схему:

```sh
docker compose -f compose.local.yaml up -d --wait
npm ci
npm run prisma:generate
npm run db:push
```

`db:push` допустим здесь только для новой пустой локальной базы `kanban_local`. Он синхронизирует текущую схему напрямую. Каталог `prisma/migrations/` существует, но его пригодность для полного bootstrap с нуля этой сверкой не проверена. Нельзя переносить эту команду в инструкцию обновления рабочей базы.

4. В первом терминале запустите приложение:

```sh
npm run dev -- --hostname localhost --port 3555
```

5. Во втором терминале из того же каталога запустите Socket.IO с явной загрузкой окружения:

```sh
node --env-file=.env --import tsx src/socket/server.ts
```

Скрипты `socket:dev` и `socket:start` сами не задают загрузку `.env`. Next.js загружает своё окружение отдельно; это не передаёт его соседнему Node-процессу.

6. Откройте [регистрацию](http://localhost:3555/sign-up), задайте собственные локальные email и пароль. Откройте [Mailpit](http://localhost:8025), найдите письмо и перейдите по ссылке подтверждения. Затем войдите и создайте свой проект. Mailpit перехватывает почту: доступ к реальному почтовому ящику для этого не нужен.

Регистрация возвращает успех даже при ошибке отправки письма (`src/app/api/auth/register/route.ts`). Если письма нет, проверьте запущенный Mailpit, SMTP-настройки и используйте повторную отправку подтверждения. Отсутствие письма не означает, что пользователь не создан.

## Порты и окружение

| Настройка | Назначение |
| --- | --- |
| `DATABASE_URL` | PostgreSQL по `127.0.0.1:55432`, база из Compose |
| `NEXTAUTH_URL`, `APP_URL`, `NEXT_PUBLIC_APP_URL` | `http://localhost:3555`: вход, ссылки писем и Socket.IO CORS |
| `NEXTAUTH_SECRET` | Собственный случайный локальный секрет |
| `NEXT_PUBLIC_SOCKET_URL`, `SOCKET_PORT` | Клиент `http://localhost:3556`, отдельный сервер 3556 |
| `SMTP_HOST`, `SMTP_PORT`, `SMTP_SECURE` | Локальный Mailpit, 1025, без TLS |
| `EMAIL_FROM` | Локальный отправитель из шаблона |
| Mailpit UI | `http://localhost:8025` |

Не смешивайте `localhost` и `127.0.0.1` в адресах приложения: origin и cookies должны соответствовать настройкам. Адрес PostgreSQL в шаблоне использует `127.0.0.1` намеренно. Socket.IO проверяет сессию через `localhost:3555`, жёстко заданный в `src/socket/server.ts`; одного изменения `PORT` недостаточно для переноса связки на другой порт.

Compose привязывает порты базы и почты к `127.0.0.1`. Сервер Socket.IO не задаёт host при `listen`, поэтому для разработки используйте закрытое локальное окружение. Его `/internal/emit` не имеет проверки учётных данных и не должен быть доступен извне.

## Демоданные и роли

`npm run db:seed` необязателен. Он создаёт/обновляет демонстрационный проект, четыре колонки и 16 задач, а также пользователя без пароля. Это не готовая учётная запись для входа. Повторный seed обновляет данные задач, поэтому не используйте его как неизменяющую проверку базы.

`SUPERADMIN_EMAIL` обрабатывается в `prisma/seed.ts`: существующий пользователь с этим адресом получает `ADMIN`, либо создаётся запись без пароля. Сама регистрация эту переменную не использует. Для локального администратора сначала зарегистрируйте и подтвердите собственный тестовый адрес, затем настройте `SUPERADMIN_EMAIL` и осознанно выполните seed в локальной базе. Не используйте адреса сотрудников. Если сначала создать запись seed, обычная регистрация этого email столкнётся с уже существующим пользователем.

## Проверки

```sh
npm run typecheck
npm run lint
npm test
npm run build
```

Детали команд и отдельной тестовой БД — в [разработке](docs/wiki/development.md). Playwright-браузеры устанавливаются отдельно; `playwright.config.ts` требует `E2E_DATABASE_URL` с именем базы, заканчивающимся на `_test`. Локальная база `kanban_local` для этих E2E не подходит. Наличие команды в документе не означает её успешное выполнение.

## Интеграции, остановка и ограничения

S3 и Sentry не нужны для базового сценария регистрации с Mailpit. Дополнительные интеграции проверяйте с отдельными тестовыми настройками. Не копируйте настоящие SMTP, AWS или Sentry реквизиты в документацию и обычный локальный запуск.

Остановите оба процесса Node через Ctrl+C, затем:

```sh
docker compose -f compose.local.yaml stop
```

Данные останутся в volume. `down -v` удаляет локальную базу и не является обычной остановкой. `npm run db:reset` также разрушителен: сбрасывает схему и запускает seed.

`ecosystem.config.js` содержит серверные абсолютные пути; не запускайте его локально без адаптации. Текущее состояние удалённого сервера, Safe Browsing и сертификатов этой сверкой не установлено. SMTP-транспорт в исходнике содержит `rejectUnauthorized: false`; перед внешним выпуском это требует отдельного решения.

[Вики](docs/wiki/README.md) связывает справки и исторические отчёты. [Состав снимка](PACKAGE_MANIFEST.md) объясняет ограничения копии. Отсутствующие скриншоты и трассы нельзя считать восстановленными по их упоминанию в текстах. Инструкция описывает ожидаемый запуск по конфигурации; чистый запуск из этой копии ещё нужно отдельно выполнить и зафиксировать.
